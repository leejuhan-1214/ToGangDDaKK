# Land / water boundary data

`land-mask.json` is generated from the **Natural Earth 1:10,000,000** land and
lakes datasets. “10m” in the source filenames means 1:10 million map scale,
**not 10-metre spatial resolution**. These polygons are generalized cartography,
not current satellite water classification. Small islands, rivers, reservoirs,
tidal coastline changes, and recent shoreline changes may be absent or displaced.
The changing Aral Sea shoreline is particularly approximate.

## Processing and accuracy

Land polygons are repaired where necessary, unioned, and have the lakes polygons
subtracted. Two-degree spatial tiles are further subdivided along coasts for fast
browser queries. Full land and water tiles use constant flags. Coastal polygon
coordinates are delta-encoded and quantized to 0.000001 degrees (about 0.11 m at
the equator); that storage precision does not improve source accuracy.

For cells at least one degree wide or high, a lower-detail global-view geometry
is used to avoid freezing the map. It is simplified at 0.01 degrees, eroded by
0.03 degrees, simplified again, and finally intersected with the original mask.
This conservative geometry stays inside the original land boundaries; narrow
islands and coastal strips may disappear at the global scale. Statistics use
the actual displayed clipped area, so the global view deliberately reports a
slightly smaller land area than full-detail coast geometry.

Both levels clip each **whole cell polygon** against land. Classifying only the
cell midpoint would allow rectangles to spill into sea and lose coastal land
cells whose midpoint happens to be water; this implementation does neither.
Point tests and route samples always use the detailed mask.

`isLandSegment` samples every 0.01 degrees or less (at most roughly 1.12 km).
It is suitable for filtering schematic educational connections, not for actual
navigation. Water narrower than the sample spacing, or absent from the source
dataset, may not be detected. Segments requiring over 20,000 intervals are
rejected rather than sampled at a wider spacing.

Environmental risk values in LAND:15 remain synthetic educational model values.
This land mask only determines where terrestrial analysis may be drawn; it does
not validate risk scores or provide evidence of observed desertification.

## Rebuild

Run these PowerShell commands **from the repository root** with Python 3.12 on
your PATH. They download inputs and install build dependencies into a temporary
scratch directory, run both scripts, and copy only the final mask into the site:

```powershell
$maskScratch = Join-Path $env:TEMP 'land15-mask-build'
New-Item -ItemType Directory -Force -Path $maskScratch | Out-Null
Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/nvkelso/natural-earth-vector/master/geojson/ne_10m_land.geojson' -OutFile (Join-Path $maskScratch 'land.geojson')
Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/nvkelso/natural-earth-vector/master/geojson/ne_10m_lakes.geojson' -OutFile (Join-Path $maskScratch 'lakes.geojson')
python -m pip install --target (Join-Path $maskScratch 'build-deps') 'shapely==2.1.2'
python scripts/build-mask.py --scratch-dir $maskScratch
python scripts/optimize-mask.py --scratch-dir $maskScratch
Copy-Item -LiteralPath (Join-Path $maskScratch 'data/land-mask.json') -Destination 'data/land-mask.json'
```

The unoptimized mask is always regenerated by the first script, so repeating
the build does not accidentally reuse an old intermediate. Both scripts accept
`--scratch-dir` (default: the current working directory); the build script also
accepts `--source-date YYYY-MM-DD` for the input download date. Keep raw GeoJSON,
`build-deps/`, and `land-mask-unoptimized.json` in scratch, outside deployed data.

The upstream `master` files can change. For a byte-for-byte rebuild of the
bundled mask, reuse source files matching its `sourceSha256` values and pass
`--source-date 2026-09-12`. The source hashes in every newly built dataset identify
its exact inputs even when the upstream data has subsequently changed.

Runtime polygon intersection uses polygon-clipping 0.15.7 (MIT); its notices and
the notices for its bundled dependencies are under `vendor/`.
